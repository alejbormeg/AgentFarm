# M1-001 — Control de alcance entre commits

Estado: primer incremento de M1; no habilita ejecución real de agentes.

## Problema y alcance

El simulador no comprueba que un cambio respete `allowed_paths`. Antes de
ejecutar trabajadores, incorporar una herramienta de solo lectura que compare
dos commits inmutables y produzca evidencia ligada al hash de la especificación.

Incluye `ScopeService`, pruebas con repositorios Git temporales, CI y documentación.
El contrato y los estados del simulador se mantienen. No incluye proveedores,
credenciales, ejecución de tareas, despliegues, aprobación humana ni fusión.

## Criterios de aceptación

1. Solo admite SHA completos de commits; el candidato debe descender de la base.
2. Detecta altas, bajas, cambios de contenido y de modo. Trata un renombrado como
   baja y alta para comprobar tanto origen como destino, sin heurísticas.
3. Las rutas son literales: `docs/` permite descendientes; `docs/a.md` solo ese
   archivo. No se aceptan rutas absolutas, escapes, glob, caracteres de control,
   nombres reservados de Windows ni segmentos con punto/espacio final. Se
   bloquean archivos cambiados que colisionen por mayúsculas/minúsculas.
4. `.github/`, `.agentfarm/`, `.git/` y `AGENTS.md` raíz están protegidos incluso
   si aparecen en `allowed_paths`; la protección ignora mayúsculas/minúsculas.
5. Los cambios de enlaces simbólicos y submódulos se bloquean sin seguirlos.
6. El informe identifica base, candidato, hash de especificación, versión de
   política, archivos y motivos. No declara implementación verificada ni aprobación.
7. Salidas: 0 si hay cambios dentro de alcance; 1 si se bloquean o no hay cambios;
   2 para entradas inválidas o fallos de Git. No modifica el checkout ni la cola.
8. Pruebas JUnit en Java 21/25, conservando las invariantes de la suite original.

## Límites y reversión

Este control inspecciona árboles Git confirmados. No inspecciona cambios locales,
archivos ignorados o no registrados, ni valida comportamiento, pruebas,
aprobaciones o aislamiento. Un informe válido pierde vigencia si cambia el SHA,
la especificación o la política; todavía no existe un consumidor que imponga esa
vigencia. La herramienta no incorpora permisos ni credenciales.

Revertir este incremento elimina una herramienta independiente sin migrar datos.
